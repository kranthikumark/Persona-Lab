# Phase 4 — Branching and comparison acceptance

Completed locally October 27, 2026. This increment verifies branch behavior using native PostgreSQL and deterministic mock generation. Phase 2's real Meta branch smoke remains separate historical evidence; no new paid provider requests were needed for these persistence and presentation checks.

## Delivered

Comparison now includes matching turn rows with trust, frustration, interest and guarantee-count changes calculated from each path's stored before-and-after snapshots. Each row identifies the recorded event and links to the actual response. Missing turns are explicitly empty; missing intermediate snapshots never borrow a final state or invent a change.

Guarantee findings distinguish shared history from findings after the split and link to their recorded message, opening shared history when needed. Comparing paths of different lengths displays an explicit caution. Opening or switching saved comparisons replays recorded data; the screen says that no new dialogue is generated by inspection. Original and alternative colors follow the existing violet/teal design system, and matching turn cards stack on narrow screens.

## Acceptance evidence

| Requirement                            | Verified result                                                                                                                                                                                                                                    |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Exact saved-state fork                 | Child stores one copied boundary snapshot with identical state, character knowledge and context version; the immutable fork pointer references the original saved snapshot.                                                                        |
| Correct prefix storage                 | Child starts with zero locally stored messages, events or retry records. Effective history resolves the original message/event IDs through the fork boundary.                                                                                      |
| Context and knowledge isolation        | Child provider input uses the pinned session scenario, the saved boundary knowledge and only prefix dialogue. Parent disclosures after that boundary are absent.                                                                                   |
| Independent parent/sibling futures     | Parent can continue after fork. Child A can continue without changing the parent or child B; B can disclose different knowledge without changing A. The original boundary snapshot stays byte-for-byte equivalent as a database record.            |
| Nested restoration                     | A child can rewind to an inherited ancestor snapshot earlier than its own fork, preserving prefix IDs and correct message/event/turn order. Later knowledge is excluded. Existing nested continuation tests also pass.                             |
| Access boundaries                      | Foreign-session and sibling-only snapshot IDs are rejected. Unauthorized forks and selecting a branch from another session return 404 and create no branch.                                                                                        |
| Actual comparison data                 | Shared history is determined by record IDs, not matching dialogue text. Snapshot deltas match stored values. Empty/same-branch comparisons and unequal lengths are explicit.                                                                       |
| Resumption and replay                  | Desktop/mobile browser flows create a named nonzero fork, generate an alternative, follow shared/divergent evidence links, reload, continue a selected path and switch back. Comparison inspection/reload/switching issues no generation requests. |
| Responsive and accessible presentation | Desktop 1440 × 1000 and mobile 390 × 844 have no horizontal overflow. Two new axe scans pass selected WCAG 2 A/AA and 2.1 AA rules. Existing accessibility journeys also pass. This is not full accessibility certification.                       |

## Limits and next phase

A new response uses the current generator and rule implementation; restoring saved state does not promise identical regenerated dialogue. Simulation changes do not establish real-world causality or a quality score. Guarantee detection remains the documented limited phrase rule. Existing history is appended to or read through the application service; database-level immutable-record triggers are not implemented. Public deployment still requires stronger creation quotas/rate limits and retention cleanup.

Next: Phase 5 — versioned, evidence-grounded rubric evaluation. No full rubric scores are claimed by this acceptance.
